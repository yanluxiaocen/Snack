# Snack · 控制台贪吃蛇

一款由 **C++17** 编写的控制台贪吃蛇小游戏：STL `deque` 承载蛇身、键盘实时操控、食物计分、撞墙与自撞判定、死亡后一键重开，并内置 **BFS 自动寻路 AI**（按 `E` 让蛇自己找最短路吃食物）；使用 **CMake** 构建（MSVC / MinGW 双编译器验证通过），**doctest** 单元测试全绿。

## ✨ 功能

- ⌨️ **实时操控**：WASD / 方向键转向，无需按回车（`_kbhit` 非阻塞轮询）
- 🐍 **自动移动**：150ms 一帧，蛇身"头进尾出"（`deque` 两端插入删除均为 O(1)）
- 🍎 **食物与计分**：随机生成且不压蛇身，吃到身体变长、分数 +1
- 💀 **碰撞判定**：撞墙或咬到自己即 Game Over，并显示最终得分
- 🔁 **重开**：死亡后按 R 再来一局，Q 随时退出
- 🤖 **自动寻路 AI**：按 `E` 切换托管——网格 **BFS** 求最短路径自动追食物、自动绕开自身
- 🎯 **手感细节**：光标回位覆盖重绘（不闪屏）、按键防排队（每帧只认最后一次操作）、长度 >1 时禁止 180° 掉头

## 🎮 操作

| 按键 | 作用 |
|------|------|
| `W` / `↑` | 向上 |
| `S` / `↓` | 向下 |
| `A` / `←` | 向左 |
| `D` / `→` | 向右 |
| `Q` | 退出游戏 |
| `R` | 死亡后重开一局 |
| `E` | 切换 AI 自动寻路（托管 / 手动） |

## 🤖 AI 迭代历程（项目亮点）

自动寻路 AI 不是一次写成的，而是**由可观测症状驱动的三轮迭代**：

| 阶段 | 策略 | 遇到的问题 | 典型单局得分 |
|------|------|-----------|-------------|
| ① | **纯 BFS 贪心**：每次求"到食物的最短路" | 只看当下最优 → 几十步后**把自己困死** | 70 ~ 80 |
| ② | **单步安全评估**：走一步后检查"头还能摸到自己的尾巴吗"（身体是会动的墙，**尾巴是唯一让路的部分**） | 视野只有一步 → 出现**活锁**：宁可永远绕圈也不敢去吃 | ~120 |
| ③ | **路径级前瞻 + 饥饿兜底**：沿整条路径虚拟推演（含吃完变长）后再判定；连续 80 步没吃到则放宽要求"赌一把" | — | **~170**（蛇长 171 节，约占场地 1/3） |

**核心结论**：从"单步贪心"到"n 步前瞻"，就是"贪心为什么不一定最优"的实战版本；而**兜底机制**保证了启发式僵死时仍能自救。

## 🛠 技术栈

- **语言**：C++17
- **构建**：CMake ≥ 3.20（MSVC 与 MinGW 双编译器验证通过）
- **测试**：doctest 单头文件框架（17 用例 / 22 断言，覆盖 Point / Snack 规则 / AutoPilot 寻路，接入 ctest）
- **STL**：`deque`（蛇身：头在 front、尾在 back）、`queue`（BFS 队列）、`vector`（访问表/父节点表）、范围 for 引用遍历
- **算法**：网格 BFS（`queue` + `visited` + **父节点表回溯路径**）；障碍建模（蛇身除尾巴——下一步它会让位）；方向数组下标与 `enum class Direction` 数值对齐
- **架构**：分层设计——`Snack` 只管游戏规则、`UI` 只管渲染、`AutoPilot` 是**纯函数**（输入蛇 + 食物 → 输出方向），AI 上线时游戏逻辑与单测零改动
- **Windows 控制台 API**：`_kbhit` / `_getch` 非阻塞读键、`SetConsoleCursorPosition` 覆盖重绘、`SetConsoleOutputCP(CP_UTF8)` 中文输出
- **工程实践**：`enum class Direction` 消灭魔法数字；成长标志"先标记、move 里消化"避免同帧竞争；UI 与游戏逻辑分层（UI 只读状态）；UTF-8 源码统一

## 🔨 构建与运行

**环境**：CMake ≥ 3.20 + 支持 C++17 的编译器

```bash
cmake -S . -B build
cmake --build build
```

运行与测试（产物路径随生成器不同）：

```bash
./build/Snack.exe          # MinGW 单配置生成器
./build/Debug/Snack.exe    # MSVC / Visual Studio 多配置生成器
./build/unit_tests.exe     # 运行单元测试
ctest --test-dir build --output-on-failure   # 或用 ctest 批量运行
```
